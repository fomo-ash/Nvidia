# Development and setup

## Requirements

- Docker with Compose v2 or newer; Docker Desktop is suitable on macOS/Windows.
- Python 3.12+ and kind for the owned fixture scripts. The script downloads/checksums its own pinned kubectl; it does not change the global kubectl context.
- Internet access for images, dependencies and live Nebius inference. The default path does not require a local GPU.
- For host frontend development: Node 22.12+ and pnpm 10.15.1. For AI/MCP host environments: uv 0.9.17, matching CI.

Use repository-root commands unless a service directory is specified. Run `python3.12` or an activated Python 3.12+ environment; Windows may use `python` instead.

## Environment and startup

Create `.env` from [.env.example](../.env.example) only once. Preserve an existing file. Never commit it.

| Environment names | Configuration |
|---|---|
| `POSTGRES_DB`, `POSTGRES_USER`, `POSTGRES_PASSWORD`, `DATABASE_URL` | Use matching database credentials. Compose database hostname is `db`; host processes need a reachable host URL instead. Existing database volumes retain their original credentials. |
| `GRAFANA_ADMIN_USER`, `GRAFANA_ADMIN_PASSWORD`, `GRAFANA_PORT` | Choose local credentials and an unused host port; default port is 3000. |
| `OPERATOR_SECRET`, `SESSION_SIGNING_KEY`, `SERVICE_AUTH_TOKEN` | Separate local operator/session/internal-service secrets, generated by reader setup when missing. |
| `SAMPLE_TARGET_UID`, `SAMPLE_CLUSTER_ID` | Exact registered sample identity. Reader setup updates the UID from the owned Deployment. |
| `LOCAL_DEMO_ENABLED` | Keep `false` for signed live operation. `true` enables synthetic compatibility access and is unsuitable for exposed deployment. |
| `AI_LLM_PROVIDER`, `NEBIUS_API_KEY`, `NEBIUS_BASE_URL`, `NEBIUS_MODEL` | Select `nebius`, provide a real key and a model available to that account. Example defaults use Token Factory and Nemotron 3 Nano. Groq is an optional development provider with its own key/base/model. |
| `ANALYSIS_ENABLED` | Set `true` for model-backed investigation; `false` retains physical evidence without inference. |
| `ANALYSIS_TIMEOUT_SECONDS`, `ANALYSIS_MAX_COMPLETION_TOKENS` | Retained-analysis caps: up to 45 seconds and 8,192 completion tokens. |
| `VITE_API_BASE_URL`, `CORS_ORIGINS` | Use a consistent browser/API hostname, normally localhost. CORS is not authentication. |

Bootstrap the fixture before using the kind overlay:

```sh
python3.12 scripts/kind_fixture.py up
python3.12 scripts/configure_investigation.py
# Complete the environment settings above, then:
docker compose -f compose.yaml -f compose.kind.yaml up --build --wait --wait-timeout 180
python3.12 scripts/kind_fixture.py status
```

Reader setup provisions a 24-hour namespace-scoped token and Kubernetes CA files in ignored `.local/kind/reader`. Refresh on expiry or cluster recreation, then recreate the overlay services. It preserves existing model credentials and never mounts the developer admin kubeconfig into application containers.

API migrations run at startup. Open http://localhost:5173, sign in with the configured operator secret and report the displayed target. Initial collection can be incomplete if the registered UID or token is stale. Container health does not verify provider credentials, source reachability or target registration.

The base `compose.yaml` starts the console, API, database, AI, MCP, monitoring, compatibility Laya and optional idle Discord worker; it does not start the live collector. The kind overlay adds its worker and sample networking. [Discord](DISCORD_INTEGRATION.md) and [guarded execution](MCP_KUBERNETES.md) require separate optional configuration.

## Explicit synthetic mode

For a credential-free synthetic foundation smoke, use the base stack with local demo access explicitly enabled:

```sh
LOCAL_DEMO_ENABLED=true docker compose up --build --wait --wait-timeout 180
docker compose run --rm api python -m app.seed
python3.12 scripts/smoke.py
```

PowerShell sets `$env:LOCAL_DEMO_ENABLED = "true"` before the Compose command and removes that session override afterward. Do not treat seeded incidents, synthetic billing or an unavailable execution adapter as live recovery. The seed adds a sample only when the incident table is empty. To return to authenticated live mode, remove the shell override, keep `.env` demo access false and recreate the kind-overlay stack.

## Checks and contracts

The checks project uses a separate disposable database, not the application volume:

```sh
docker compose -f compose.checks.yaml run --build --rm api-checks
docker compose -f compose.checks.yaml run --build --rm api-postgres-checks
docker compose -f compose.checks.yaml run --build --rm web-checks
docker compose -f compose.checks.yaml run --build --rm ai-checks
docker compose -f compose.checks.yaml run --build --rm mcp-checks
```

Direct lint/type/contract checks:

```sh
docker compose -f compose.checks.yaml run --build --rm api-checks ruff check app tests scripts alembic
docker compose -f compose.checks.yaml run --build --rm api-checks ruff format --check app tests scripts alembic
docker compose -f compose.checks.yaml run --build --rm api-checks python scripts/export_openapi.py --check
docker compose -f compose.checks.yaml run --build --rm web-checks pnpm lint
docker compose -f compose.checks.yaml run --build --rm web-checks pnpm typecheck
docker compose -f compose.checks.yaml run --build --rm web-checks pnpm contracts:check
```

Root scripts use `ruff.toml`; check `ruff check scripts tests` and `ruff format --check scripts tests` too. CI additionally runs sample/fixture tests, AI/MCP checks and a base-stack synthetic HTTP smoke. Tests present in source are not evidence of a successful live integration.

After an intentional API change, regenerate `apps/api/openapi.json` with `python apps/api/scripts/export_openapi.py`, then `pnpm contracts:generate` for the web schema. Review both outputs. `--check` and `pnpm contracts:check` detect drift; export does not start the API or connect to a database.

## Host development

Keep API, AI and MCP in separate Python environments: each uses the top-level package name `app`. Install API development dependencies with `pip install -e 'apps/api[dev]'` in its environment. From `apps/api`, use a deliberate `DATABASE_URL`, run `alembic upgrade head` and start `uvicorn app.main:app --reload`.

AI/MCP frozen environments:

```sh
uv sync --project apps/ai --frozen --extra dev
uv sync --project apps/mcp --frozen --extra dev
(cd apps/ai && uv run --frozen --extra dev pytest -q)
(cd apps/mcp && uv run --frozen --extra dev pytest -q)
```

For the frontend, run `pnpm install --frozen-lockfile` then `pnpm --filter @fixproof/web dev`. Root scripts provide lint, typecheck, tests and build. Browser E2E needs a prepared running fixture and local operator configuration; `PLAYWRIGHT_CHANNEL=chrome pnpm test:e2e` uses installed Chrome. These tests can create live reports. Follow the [demo runbook](DEMO_RUNBOOK.md) for faulting and action scripts.

## Troubleshooting and shutdown

- Port collision: inspect existing listeners and choose `GRAFANA_PORT` before recreating Grafana. Do not assume another local service belongs to FixProof.
- Pull/checksum/DNS failure: retry the specific pinned image or dependency after checking Docker networking/proxy settings. Do not substitute image tags or delete application volumes to fix a registry issue.
- Kubernetes errors: check owned fixture identity, `SAMPLE_TARGET_UID`, token expiry and kind-network connectivity. Refresh reader configuration rather than bypassing UID checks.
- Model 503 or `needs_review`: inspect retained source/model gaps and private service logs. Never replace a failed live run with synthetic success.

`docker compose down` stops containers while retaining PostgreSQL data. `docker compose -f compose.checks.yaml --profile checks down` cleans up the separate check project. `make reset-data` and `down -v` delete volumes; they are not routine reset commands. Reset or tear down only the owned sample through the [kind runbook](../infra/kind/README.md).
